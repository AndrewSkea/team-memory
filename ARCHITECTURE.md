# team-memory v2 — Architecture

> Status: proposed · Supersedes the v1 design (GitHub-API-as-database, Claude Code only)

## 0. The one-paragraph version

`team-memory` is a **single Go binary** that keeps a **local-first memory store** on your
machine: SQLite for speed, Markdown-in-git for truth. It installs into Claude Code and
Codex with one command each, injects relevant memories into your agent's context in under
50 ms, captures new ones in the background, and gates every write behind a **trust mode**
you choose. A local web UI — reachable from your phone on the LAN — is where you capture
notes on the move, approve what's queued, and rescue memories that are decaying. No server,
no account, no PAT required to start. Git is the only sync protocol.

---

## 1. Goals, and the constraints that follow

| Goal | Hard constraint it imposes |
|---|---|
| One line to install, one line to wire into a CLI | Single static binary, no runtime deps, no cgo, no Node/Python |
| Completely local | Zero network in the read path. Network only for git sync + optional LLM |
| Very fast | Retrieval p95 < 25 ms warm. Capture must never block the agent's turn |
| Works with Claude Code *and* Codex | Agent integration is an **adapter**, never baked into the core |
| Works with subscriptions *and* API keys | Provider layer with credential resolution; prefer delegating to the vendor CLI |
| Three levels of approval | Memory is a **state machine**, not a file append |
| Phone-accessible UI | LAN bind + device pairing + PWA offline capture |
| Team sharing | Git, with a data layout that makes merges structurally conflict-free |

### Non-goals
- No hosted service, no accounts, no telemetry, ever.
- No vector database, no external index process, no Docker.
- Not a wiki. Memories are short, atomic, and machine-retrievable; long docs stay in your repo.

## 2. Shape: one binary, three surfaces, two storage layers

```
                     ┌──────────────────────────────────────────────┐
   Claude Code ──────┤ hooks + slash commands + MCP  (adapter)      │
   Codex       ──────┤ MCP + AGENTS.md block + notify (adapter)     │
   Phone/Browser ────┤ HTTP + PWA over LAN                          │
                     └───────────────────┬──────────────────────────┘
                                         │
                      ┌──────────────────▼──────────────────┐
                      │  team-memory (one binary)           │
                      │  ┌───────────┐    ┌──────────────┐  │
                      │  │ tm  (CLI) │    │ tm daemon    │  │
                      │  │ thin,     │    │ long-lived:  │  │
                      │  │ read-fast │    │ UI, git,     │  │
                      │  │           │    │ extract, GC  │  │
                      │  └─────┬─────┘    └──────┬───────┘  │
                      └────────┼─────────────────┼──────────┘
                               │                 │
                    ┌──────────▼─────┐   ┌───────▼────────────┐
                    │ memory.db      │   │ memories/ (git)    │
                    │ SQLite + FTS5  │   │ one .md per memory │
                    │ DERIVED INDEX  │   │ SOURCE OF TRUTH    │
                    └────────────────┘   └────────────────────┘
```

### The governing principle

> **Git is the truth. SQLite is a rebuildable cache.**

Every memory is one Markdown file with YAML frontmatter, committed to git. The SQLite
database holds nothing that cannot be regenerated by `tm reindex` in a few seconds. This
single decision buys four things at once:

1. **Sync is just git.** No custom protocol, no server, no conflict resolution service.
2. **Corruption is not data loss.** Delete `memory.db`, reindex, carry on.
3. **Memories are reviewable.** Team memories arrive as a normal PR diff.
4. **Portability.** Your knowledge outlives this tool — it's a folder of Markdown.

And the inverse: because SQLite is *only* an index, we can put anything in it that makes
retrieval fast without worrying about migration pain.

### Why a daemon *and* a thin CLI

Hooks fire on the critical path of every prompt. They must never wait on a process that
might not be running.

- **`tm` (CLI)** opens SQLite directly in WAL mode and answers reads with no IPC. Writes go
  into an **outbox table** — a durable local queue — and return immediately.
- **`tm daemon`** drains the outbox into git, runs extraction, serves the UI, and runs the
  decay GC. It is auto-spawned on first use and idle-exits after 30 minutes.

If the daemon is dead, retrieval still works, capture still works (it queues), and the next
CLI invocation restarts it. **Nothing on the agent's critical path can be blocked by a
background process.** That's the whole reason for the split.

## 3. Data model

### 3.1 On disk

```
~/.team-memory/
  config.toml               # single config surface — CLI and UI read the same file
  memory.db                 # SQLite index (derived, .gitignore'd)
  outbox/                   # durable write queue, survives crashes
  install-manifest.json     # every file tm touched, for exact uninstall
  personal/                 # scope: personal — never pushed to a team remote
    memories/2026/01H....md
  team/                     # scope: team — a git clone of your shared memory repo
    memories/2026/01H....md
    archive/
<your-project>/.team-memory/  # scope: project — committed alongside the code
    memories/01H....md
```

### 3.2 A memory

```markdown
---
id: 01HQ8XZ4F7K2N9M3P5R7T9V1W3     # ULID — sortable, collision-free, = filename
v: 1
class: gotcha                       # preference | decision | gotcha | fact | howto | context
scope: project                      # personal | project | team
title: Staging Redis evicts keys under 4 KB
body_hash: sha256:...
created: 2026-08-21T10:14:02Z
author: andrew
confidence: 0.82
pinned: false
ttl_class: medium                   # drives the decay half-life
tags: [redis, staging, infra]
projects: [github.com/acme/api]
keys:                               # retrieval keys — write-time query expansion
  - redis staging eviction maxmemory-policy
  - cache keys disappearing staging
  - why does staging lose sessions
supersedes: 01HQ2...                # optional; forms a provenance chain
source:
  kind: session                     # session | manual | ui | import
  agent: claude-code
  session: 4f3a...
  cwd: /Users/andrew/src/api
  commit: a91c2f1
---

Staging Redis runs `maxmemory-policy allkeys-lru` with a 512 MB cap, so session keys
get evicted under load. Production uses `noeviction`. If sessions vanish only in
staging, this is why — don't chase the auth code.
```

**The `keys` field is the performance trick.** The extractor already has an LLM in hand at
write time, so it generates 3–6 alternate phrasings — the questions this memory answers.
Those go into the full-text index alongside the body. This buys most of the recall benefit
of semantic search **while keeping the read path pure lexical BM25 with zero vector math
and zero model in memory.** Query expansion moves from read time (slow, every query) to
write time (once, off the critical path).

### 3.3 SQLite schema (sketch)

```sql
CREATE TABLE memories (
  id TEXT PRIMARY KEY, scope TEXT, class TEXT, state TEXT,
  title TEXT, body TEXT, created INTEGER, author TEXT,
  confidence REAL, pinned INTEGER, ttl_class TEXT,
  last_used INTEGER, use_count INTEGER, score REAL,
  supersedes TEXT, file_path TEXT, body_hash TEXT
);
CREATE VIRTUAL TABLE memories_fts USING fts5(
  title, body, keys, tags, content='memories', tokenize='porter unicode61'
);
CREATE TABLE projects (memory_id TEXT, project TEXT);
CREATE TABLE outbox  (seq INTEGER PRIMARY KEY, op TEXT, payload TEXT, created INTEGER);
CREATE TABLE usage   (memory_id TEXT, at INTEGER, kind TEXT); -- injected | cited | edited
```

`modernc.org/sqlite` — pure Go, FTS5 included, so cross-compilation for every platform stays
a single `GOOS=... go build` with no C toolchain.

### 3.4 Why merges are structurally conflict-free

Filename **is** the ULID. Two people never write the same file, so git never sees a content
conflict on a memory. The only mergeable artifacts are derived indexes (`INDEX.md`,
`by-tag/`) — those are marked `merge=ours` in `.gitattributes` and regenerated after every
merge. **Concurrent team writes cannot conflict by construction**, which is what makes
"git as the database" actually hold up with more than one person.

## 4. The memory lifecycle

```
                  ┌─────────► rejected ──────► (kept 30d, then purged)
                  │
 candidate ───────┼─────────► queued ────────► active ───► dormant ───► expiring ───► archived
 (extracted)      │           (awaiting        (indexed,   (below      (in the      (moved to
                  │            approval)        injected)   θ₁, not     Decay Bin,   archive/,
                  └─────────► active            ▲           injected)   counting     never hard
                              (auto mode)       │                       down)        deleted)
                                                │                          │
                                          reinforcement ◄──────── rescue ──┘
                                          (used in a session)
```

**Decay score**, recomputed nightly by the daemon:

```
score = w₁·exp(−Δt_last_used / τ(ttl_class))
      + w₂·log(1 + use_count)
      + w₃·pinned
      + w₄·confidence
      − w₅·superseded_penalty
```

Half-lives (`τ`): `preference` 365 d · `decision` 180 d · `fact` 180 d · `howto` 120 d ·
`gotcha` 90 d · `context` 30 d.

**Reinforcement matters more than decay.** A memory that keeps getting injected and cited
never decays. A memory nobody ever needed drifts out of retrieval within a quarter without
anyone curating anything. This is the mechanism that stops the store rotting — the thing
every "team wiki" fails at.

**Nothing is ever hard-deleted.** `expiring` → `archived` moves the file to `archive/`; git
history keeps it forever. The Decay Bin in the UI shows what's on the way out with a
countdown and one-click **Rescue** (which pins + resets the clock) or **Delete now**.

**Superseding, not duplicating.** At capture time the extractor searches the existing store
first. If a candidate contradicts or refines an existing memory it emits
`supersedes: <id>`, the old memory moves to `superseded`, and the chain stays readable. This
is where memory systems usually die — 40 near-identical entries about the same thing — so
dedupe is a first-class step in the pipeline, not a cleanup job.

## 5. Trust modes — the three approval levels

Set globally, overridable per project **and** per memory class.

| # | Mode | What happens | Where you approve |
|---|---|---|---|
| 1 | `auto` | Extracted → written → committed immediately | Nowhere. Undo from the digest or `tm undo` |
| 2 | `inline` | Extracted → held → surfaced in your terminal at session end | In Claude Code / Codex, per memory |
| 3 | `queue` | Extracted → held. Nothing written | Web UI inbox, per memory |

```toml
[trust]
default = "inline"

[trust.by_scope]
personal = "auto"      # your own preferences — just save them
project  = "inline"
team     = "queue"     # anything the team sees gets deliberate review

[trust.by_class]
preference = "auto"
decision   = "queue"   # decisions are consequential; look at them properly
```

Resolution: most specific wins (`class` > `scope` > `default`).

**`auto` mode still has a safety net.** Every auto-write is one git commit containing one
file, so `tm undo` is a `git revert` of a single memory. The daemon also posts a digest
("7 memories saved today") at a cadence you set.

**One rule overrides all three modes:** the redaction gate (§9). If a candidate trips secret
detection, it is forced into `queue` regardless of mode, flagged, and never written to a
shared scope until a human clears it.

### 5.1 How `inline` actually works — and an honest constraint

Claude Code owns the terminal during a session. A hook **cannot** take over stdin to read
keypresses, so a true "press y/n per memory" prompt inside a live session is not available
to us. What *is* available is a hook writing into the transcript. So `inline` is:

```
── team-memory ── 3 candidates from this session
  1  gotcha      Staging Redis evicts keys under 4 KB
  2  decision    We chose Postgres advisory locks over Redlock
  3  preference  Andrew prefers table-driven tests

/tm ok 1 2      ·  /tm no 3      ·  /tm ok all      ·  /tm edit 2
```

You approve per memory, in the terminal, without leaving the session — just typed rather
than keypressed. Those slash commands shell out to `tm approve` and return in single-digit
milliseconds.

For anyone who wants the full keyboard experience, `tm review` in a second terminal is a
real full-screen TUI (Bubble Tea) with j/k/a/r/e/space bindings.

> **Verify before building:** if the installed Claude Code version exposes an interactive
> hook channel, the adapter should upgrade to it. The capability probe in §6.3 is where that
> decision belongs — not hard-coded anywhere in the core.

## 6. Agent integration — adapters, not entanglement

The core knows nothing about Claude Code or Codex. Each adapter implements:

```go
type Adapter interface {
    Name() string
    Detect() (installed bool, version string, err error)
    Capabilities() Caps          // probed, never assumed
    Install(cfg Config) (Manifest, error)
    Uninstall(Manifest) error
    Doctor() []Finding
}

type Caps struct {
    ContextInjection  bool // can we push memories in at session start?
    JITRetrieval      bool // can we retrieve per-prompt?
    SessionCapture    bool // can we read the transcript at session end?
    SlashCommands     bool
    MCP               bool
}
```

`tm install --cli codex` probes what that version of Codex actually supports and installs
the best available subset, then `tm doctor` tells you plainly what you got and what you
didn't. **The system degrades one capability at a time instead of failing whole.**

### 6.1 Claude Code

| Need | Mechanism |
|---|---|
| Inject relevant memories at session start | `SessionStart` hook → memory brief, token-budgeted |
| Just-in-time retrieval per prompt | `UserPromptSubmit` hook → `additionalContext` |
| On-demand search/write mid-session | MCP server: `memory_search`, `memory_add`, `memory_cite` |
| Capture at session end | `Stop` + `PreCompact` + `SessionEnd` hooks → transcript to extractor |
| Approve / search by hand | Slash commands: `/tm`, `/remember`, `/tm ok`, `/tm no` |

Preferred packaging is a **Claude Code plugin** — one `plugin.json` bundling hooks, commands,
and the MCP server, so install and uninstall are atomic. `tm install --cli claude-code`
writes settings directly when the plugin path isn't available.

### 6.2 Codex

| Need | Mechanism |
|---|---|
| Tools mid-session | MCP server in `~/.codex/config.toml` → `[mcp_servers.team_memory]` |
| Context injection | A `team-memory` delimited **managed block** in `AGENTS.md`, refreshed per project by the daemon |
| Capture | `notify` program on turn events → reads the session rollout → extractor |
| Approval | `tm review` TUI + the web UI (Codex has no slash-command surface for us) |

Codex's hook surface is thinner than Claude Code's, so **`inline` mode on Codex degrades to
`queue` by default** and `tm doctor` says so out loud. Verify the `notify` and rollout paths
against the installed version at implementation time rather than trusting this table.

### 6.3 The context budget

Injection is capped — **default 800 tokens, never more than 2% of the context window.**
The retriever fills that budget by score and stops. Memories are rendered flat and compact:

```
## Memory (team-memory · 6 entries · /tm why for sources)
- [gotcha] Staging Redis evicts keys <4KB — maxmemory-policy allkeys-lru, 512MB cap.
- [decision] Postgres advisory locks over Redlock — single-writer, no extra infra.
```

An agent memory system that eats context is a net negative. The budget is a hard invariant,
enforced in tests.

## 7. Capture and retrieval pipelines

### Capture (asynchronous, never on the critical path)

```
transcript ─► segment ─► candidate extraction (LLM or rules)
           ─► dedupe/supersede against existing store
           ─► redaction gate  ─► classify + score + generate retrieval keys
           ─► trust-mode router ─► [auto: write] | [inline/queue: hold]
           ─► outbox ─► daemon ─► git commit ─► SQLite index
```

The hook's entire job is to drop the transcript reference into the outbox and exit. Total
hook cost: **< 15 ms**. Everything after that happens in the daemon, after the agent has
already given you back your terminal.

### Retrieval (synchronous, hot)

```
query ─► normalize + expand ─► FTS5 BM25 over (title, body, keys, tags)
      ─► rescore: scope weight · project match · recency · use_count · pinned
      ─► supersede-chain collapse (only the newest survives)
      ─► token-budget fill ─► render
```

No LLM. No network. No embedding model. Pure SQLite. That's how it stays under 25 ms.

**Optional semantic layer.** Vector search is opt-in and pluggable: point
`[embeddings] endpoint` at any OpenAI-compatible server (Ollama, llama.cpp, LM Studio) or a
cloud provider, and the daemon backfills embeddings and fuses vector hits with BM25 via
Reciprocal Rank Fusion. **Nothing is bundled and nothing is required** — the default install
has no model, no cgo, and no download. Write-time key expansion already covers most of the
gap.

## 8. Providers and authentication

The LLM is needed for exactly three things — extraction, dedupe judgement, summarisation —
**all off the critical path, all optional.** Credential resolution, first match wins:

| # | Source | Setup cost | Notes |
|---|---|---|---|
| 1 | **Delegate to the installed vendor CLI** — `claude -p`, `codex exec` | **Zero** | Reuses the login you already have, subscription included. **Default.** |
| 2 | Stored OAuth token — `tm auth login claude` | One browser round-trip | Drives the vendor's own login (`claude setup-token` / `ant auth login`), stores the result in the OS keychain |
| 3 | API key — `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` | Paste once | Keychain-backed, never written to a dotfile in plaintext |
| 4 | Local OpenAI-compatible endpoint | Point at a URL | Fully offline operation |
| 5 | None | — | Rule-based extraction only; explicit `/remember` still works completely |

**The subscription path, concretely.** You asked for "open the browser, log in, save the
token, seamless." The right way to deliver that is to **drive the vendor's own login flow,
not reimplement it**: `tm auth login claude` shells out to the Claude CLI's token setup,
which opens the browser, you approve, and the resulting token lands in your OS keychain.
Reimplementing Anthropic's OAuth endpoints ourselves would be fragile, would break on every
upstream change, and would sit outside what's sanctioned. Driving the vendor CLI gets the
identical UX and stays supported.

Better still is path 1: if you have Claude Code or Codex installed and logged in — which you
do, since you're installing a plugin for it — **there is nothing to authenticate at all.**
That is the default, and most users will never see an auth prompt.

**Model policy.** Extraction and classification are short, structured, high-volume calls, so
the shipped default is `claude-haiku-4-5` ($1/$5 per MTok, 200K context) — roughly an order
of magnitude cheaper than the Opus tier and entirely adequate for the job. Any model is
configurable per task:

```toml
[models]
extract   = "claude-haiku-4-5"
dedupe    = "claude-haiku-4-5"
summarize = "claude-sonnet-5"
```

Secrets live in the OS keychain (Keychain / libsecret / Windows Credential Manager), with a
`0600` file fallback. **No credential is ever stored in browser `localStorage`** — that's a
specific regression from v1 that the device-token model in §10 replaces.

## 9. The redaction gate

Everything bound for a shared scope passes through, before it is written anywhere:

1. **Pattern scan** — API keys, PATs, JWTs, private keys, connection strings, cloud creds.
2. **Entropy scan** — high-entropy strings that look like secrets but match no pattern.
3. **Environment correlation** — values seen in the session's `.env` or exported vars.
4. **PII heuristics** — emails, phone numbers, personal paths.

A hit **forces the candidate into `queue`**, flags the span, and offers redact-and-keep or
discard. A trust mode of `auto` does not bypass this — it cannot. The failure mode this
prevents (a teammate's API key committed to a shared memory repo, forever, in git history)
is severe enough to be worth the one rule that has no override.

## 10. The local UI

`tm serve` — embedded in the binary via `embed.FS`, no separate deploy, no build step at
runtime.

| Page | Purpose |
|---|---|
| **Capture** | One big box. Type, hit save, done. The reason the phone access exists |
| **Inbox** | The `queue`. Approve / reject / edit, keyboard-driven, bulk actions |
| **Library** | Search and browse everything, filter by scope, class, tag, project |
| **Decay Bin** | What's expiring, with countdowns. Rescue or delete |
| **Timeline** | What was learned when, grouped by session and project |
| **Settings** | Trust modes, scopes, sync remotes, paired devices, provider |

### LAN access and pairing

- Default bind is `127.0.0.1:7777`. LAN exposure is **explicit opt-in**: `tm serve --lan`.
- On `--lan`, the terminal prints a **QR code**. Your phone scans it, hits `/pair` with a
  single-use code (10-minute TTL), and receives a long-lived **device token**.
- Every endpoint except `/pair` requires that token as a bearer header. **No cookie auth**,
  so CSRF is structurally impossible. Devices are listed and revocable in Settings.
- Optional mDNS so the phone can reach `http://team-memory.local:7777`.
- The UI is a **PWA**: installable, and capture works offline — notes queue in IndexedDB and
  flush when you're back on the network. Capture on a phone that only sometimes has your LAN
  is the actual use case, so the outbox pattern applies on the client too.

The UI talks to the same local HTTP API the CLI uses. **One API, one config file, one source
of truth** — v1's split between CLI config and browser `localStorage` is gone.

## 11. Sync

```
tm sync   =   git pull --rebase  →  reindex  →  git push
```

Runs on a timer in the daemon, on demand from the UI, and after every approval batch.
Because filenames are ULIDs (§3.4), the rebase cannot conflict on memory content.

Three scopes, three destinations:

- **personal** — `~/.team-memory/personal/`, optionally its own private repo. Never pushed
  to a team remote. Enforced in code, not by convention.
- **project** — `<repo>/.team-memory/`, committed with your code. Travels with the branch,
  reviewed in the PR that introduced it, and clones with the repo for free.
- **team** — a shared memory repo. `tm sync` keeps it current. Optional PR-based approval
  for teams that want a second gate beyond `queue`.

Retrieval unions all three and ranks across them, with a configurable scope weight so
project-local memories beat general team ones when you're in that project.

## 12. Performance budgets

Enforced by benchmarks in CI against a synthetic 10,000-memory corpus. A regression fails
the build — otherwise "fast" erodes one commit at a time.

| Path | Budget (p95) |
|---|---|
| `tm search` — cold process, no daemon | < 40 ms |
| `tm search` — warm daemon | < 10 ms |
| `SessionStart` injection, end to end | < 60 ms |
| `UserPromptSubmit` JIT retrieval | < 25 ms (skipped if it would exceed) |
| Capture hook (enqueue only) | < 15 ms |
| `tm reindex`, full rebuild from Markdown | < 3 s |
| Binary size | < 20 MB |
| Idle daemon RSS | < 40 MB |

## 13. Repository layout

```
cmd/tm/                  # single binary; `tm daemon` is a subcommand
internal/
  store/                 # SQLite schema, migrations, queries, outbox
  gitstore/              # commit loop, sync, archive, undo
  memory/                # domain model, state machine, decay scoring
  capture/               # extraction (LLM + rules), dedupe, supersede
  retrieve/              # BM25, rescoring, fusion, token budgeting, rendering
  redact/                # the gate
  provider/              # cli-delegate | anthropic | openai | local | none
  adapters/
    claudecode/          # hooks, slash commands, plugin manifest, install
    codex/               # config.toml, AGENTS.md block, notify, install
  mcpsrv/                # MCP server
  api/                   # local HTTP API (CLI and UI share it)
  webui/                 # embedded SPA assets
  auth/                  # keychain, device tokens, pairing, QR
  config/
web/                     # SPA source
docs/architecture/
```

Dependency rule: `adapters/` and `webui/` may import the core; **the core may never import
an adapter.** Adding a third agent CLI later must not touch a single file under
`internal/memory/`.

## 14. Build order

Each phase ships something usable on its own.

| Phase | Delivers | Done when |
|---|---|---|
| **1 — Spine** | Store, git backend, memory model, `tm remember` / `search` / `reindex` | You can add and find memories from a terminal, offline |
| **2 — Claude Code** | Adapter, hooks, MCP, slash commands, `tm install --cli claude-code` | Memories inject and capture end-to-end in a real session |
| **3 — Trust** | State machine, all three modes, `tm review` TUI, redaction gate | Nothing is written without the approval level you chose |
| **4 — UI** | Daemon HTTP API, embedded SPA, `--lan`, pairing, PWA | You capture a note from your phone and approve it there |
| **5 — Codex** | Adapter, capability probe, `tm doctor` | Same install one-liner, honest degradation report |
| **6 — Longevity** | Decay GC, Decay Bin, supersede chains, digests, team sync | The store stays clean at 1,000+ memories without curation |

Small but real: the Haiku-pinned cheap-model instinct, the `claude` CLI delegation for auth,

## 16. Defaults I chose — say the word to flip any of them

| Decision | Default | The alternative |
|---|---|---|
| Language | Go — matches v1, single static binary, trivial cross-compile | Rust: smaller/faster, slower to build, no reuse |
| Default trust mode | `inline` for project, `queue` for team, `auto` for personal preferences | Start everyone at `queue` and let them loosen it |
| Semantic search | Off by default, opt-in via any OpenAI-compatible endpoint | Bundle a quantised ONNX embedder (+130 MB, cgo, slower install) |
| Team scope | A separate shared memory repo | `.team-memory/` inside each project repo only |
| Claude Code packaging | Plugin, with direct settings-write as fallback | Settings-write only |
| Command name | `team-memory`, with `tm` as the short alias | Something shorter as primary |
